1. Overview                                                         *dotfiles*

`init.lua` loads options, keymaps, and lazy.nvim, then imports every plugin
spec in `lua/plugins/`. Helpers live in `lua/config/utils.lua`, and its
submodules in `lua/config/utils/` load on first access.

Longer write-ups are in `docs/ARCHITECTURE.md`, `docs/ADDING_A_LANGUAGE.md`,
and `CONTRIBUTING.md`.

==============================================================================
2. Load order                                                *dotfiles-load-order*

`init.lua` runs these in order:

    1. `config.options`, then `personal.options`
    2. `config.keymaps`
    3. lazy.nvim bootstrap and `require("lazy").setup`
    4. `config.usercmds`, then `config.autocmds`
    5. `personal.init`

Each personal file is loaded only if it exists.

==============================================================================
3. Plugin specs                                                *dotfiles-plugins*

Specs live in `lua/plugins/`, grouped by theme: `coding.lua`, `editor.lua`,
`ui.lua`, `lsp.lua`, `treesitter.lua`, `formatting.lua`, `colorscheme.lua`,
`utils.lua`, `java.lua`, and `legacy.lua`.

Every spec declares a trigger: `event`, `cmd`, `ft`, or `keys`. A spec with
`lazy = false` needs a justification in its commit message or PR text.

Format with `stylua`. CI runs `stylua --check .`.

==============================================================================
4. Personal overlay                                          *dotfiles-personal*

`lua/personal/` is gitignored and optional. Its three hooks run in this order:

    `lua/personal/options.lua`   after `config.options`
    `lua/personal/plugins/`      imported at lazy spec index 2
    `lua/personal/init.lua`      last, after plugins are set up

A personal spec for a plugin that already exists in `lua/plugins/` merges with
the base spec, so it can extend `opts` or toggle `enabled`.

==============================================================================
5. Lockfiles                                                 *dotfiles-lockfiles*

`lazy-lock.json` pins plugin commits. super_lazy.nvim manages it and keeps a
separate lockfile for `lua/personal`.

`mason-lock.json` pins tool versions. mason-lock.nvim records only the
packages in `locked_packages`, set in `lua/plugins/lsp.lua`.

Run `:Lazy` to update plugins, and commit the lockfile change with the update.

==============================================================================
6. Adding a language                                          *dotfiles-language*

Up to three edits, described in `docs/ADDING_A_LANGUAGE.md`:

    `lua/plugins/lsp.lua`                  `server_defs` and `filetype_tooling`
    `lua/config/utils/treesitter.lua`      `ensure_installed`
    `lua/plugins/formatting.lua`           `formatters_by_ft`

Every server named in `filetype_tooling` must be a key in `server_defs`.
